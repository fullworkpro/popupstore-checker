# 小红书平台扩展调研（2026-10-26）

> 结论：**暂不实施**。本文备案"微信小程序能否发布到小红书"的调研结果，以及日后要做的开工清单。
> 平台政策变动频繁，实际动工前请以 Builder Hub 现场页面与官方 Skill 为准。

## 一、核心结论

| 问题 | 答案 |
|---|---|
| 微信小程序能"换 AppID 直接打包"到小红书？ | ❌ 不能。小红书没有微信 WXML/WXSS 兼容层，不是同一套 DSL。 |
| 小红书小程序（渐进 wechat-like）个人主体能上？ | ❌ 不支持。仅境内企业 / 个体工商户入驻。 |
| 现状下个人能走的路？ | ✅ **小红书「小工具」（RedSkill / Builder Hub）**，个人创作者账号可提交。 |

## 二、小红书三套轻应用体系（主体要求完全不同）

| 体系 | 主体要求 | 联网 | 交易 | 备注 |
|---|---|---|---|---|
| 小程序 | 企业 / 政府事业单位 / 其他组织 / **个体工商户**（不接受个人） | ✅ | ✅ | 需专业号认证（约 600 元/年）+ 主体认证 + 小程序备案（平台 1~3 天 + 通管局 1~20 天）；一店仅一个品牌；服务类目审核严 |
| 小组件 | 仅个人开发者 | 受限 | ❌ | 邀请制灰度，需被邀请才能创作 |
| 小工具 RedSkill | 个人创作者账号 | ❌ 纯离线 | ❌ | Builder Hub → 小工具，PC 端创作 + 移动端挂载在笔记下方 |

## 三、「小工具」的关键约束（决定了产品形态）

1. **纯离线 H5 沙箱**：本质是跑在受限 WebView 里的标准 Web 应用（HTML/CSS/JS），
   **禁止任何网络请求**，所有页面、脚本、图片、字体必须打进 zip（经验上限约 10MB，入口 `index.html`）。
2. **无原生桥接**：不能调宿主登录、支付、跳转等原生能力；可用 Web 侧的相册 / 摄像头 / 本地存储。
3. **发布流程**：Builder Hub 上传 zip → 部署（名称/简介/图标）→ 预览二维码 → 提交审核 → 上线 → 发笔记时挂载。
4. **每次数据更新都要重新打包 + 提审**，不适合高频实时数据。
5. 官方提供 AI 用的打包 Skill（`minitool-zip-builder` 类），动工时优先用它做最后的工程校验与出包，
   不要手工右键压缩。真机验证必做：PC 预览通过 ≠ 手机 WebView 通过（Canvas/图片/触摸/存储都需实测）。

## 四、本项目（PopStore）适配度

| 现有能力 | 离线小工具能否支持 |
|---|---|
| 城市筛选 / 列表 / 详情查看 | ✅ 数据打进 JSON 内置即可 |
| 关键词或 IP 检索 | ✅ 本地过滤 |
| 实时更新（新活动自动出现） | ❌ 必须发版才能更新 |
| 店铺实拍图 | ⚠️ 全内置会迅速撑爆包体；**决策：不带图，纯文字清单** |
| 收藏、扫码、跳转小程序 | ❌ 无原生能力 |

## 五、建议的产品形态（若日后开工）

- **名称方向**：「本周二次元快闪速查」或「附近快闪倒计时」
- **交互**：选城市 → 列出当前在档快闪（IP / 档期 / 地点 / 是否需预约 / 剩余天数）→ 点开看详情
- **配笔记**：发一篇「10 月 XX 城二次元快闪合集」笔记，下方挂载该工具，用笔记承接图片与流量
- **更新节奏**：与公众号周报同步，每周重新打包提审一次（约 10 分钟/次）

## 六、开工清单（可执行）

1. 数据导出：新写脚本把 `status=published` 的店铺导成精简 JSON
   （字段：id / title / city / address / start_date / end_date / reservation / tags），**不含 images**。
2. 单页离线 H5：城市 Tab + 列表 + 详情弹层，纯静态，无网络请求，控制在几百 KB。
3. 按官方 Skill 做构建校验 → 出 zip → Builder Hub 上传 → 部署 → 真机扫二维码验证 → 提审。
4. 首版建议只覆盖 1~2 个热门城市，验证流程后再扩。

## 七、若要走"完整能力"路线（另一条路）

办个体工商户执照 → 专业号认证 → 入驻小红书小程序 → 用 uni-app / Taro 多端编译现有
`miniprogram/`（约 2370 行）目标平台改为小红书小程序，并对齐其 DSL 与 API 差异。
成本：执照 + 600 元/年 + 备案 1~20 天 + 约一周开发适配。
